🤖 AI Logic Analysis & Fix

### Risk Analysis
The identified vulnerability, CKV_DOCKER_3, highlights the absence of a non-root user in the Docker container. By default, Docker containers run as the root user, which has unrestricted access to the entire system. This configuration poses several risks:

1. **Security Risk**: Running processes as root inside a container can lead to privilege escalation attacks. If an attacker exploits a vulnerability within the application, they could gain root access to the host system, potentially compromising other containers and the host itself.

2. **Business Risk**: A security breach could lead to data theft, service disruption, and loss of customer trust. This could result in financial losses, legal liabilities, and damage to the company's reputation.

3. **Compliance Risk**: Many regulatory standards and security best practices require minimizing the use of privileged accounts. Failing to comply with these standards could lead to penalties and increased scrutiny from regulatory bodies.

### Corrected Code
To mitigate this risk, you should create a non-root user and switch to it within the Dockerfile. Here's how you can modify the Dockerfile:

```hcl
FROM node:14

# Create a non-root user and group
RUN groupadd -r appuser && useradd -r -s /bin/false -g appuser appuser

# Switch to the non-root user
USER appuser

RUN echo "Running on old node"
```

This change ensures that the container runs with limited privileges, reducing the risk of privilege escalation and improving the overall security posture of your application.
